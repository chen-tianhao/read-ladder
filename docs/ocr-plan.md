# 图片转文本 · 实现规格

给「自定义内容」增加拍照识别：把 1–5 张单语种打印稿照片转成可朗读的分块文本，插图原样保留。

**状态**：方案定稿，尚未实现。本文档是实现依据，决策变更须回写此处。

---

## 1. 目标与非目标

### 目标

- 单语种打印稿（全中文，或全英文）拍照后，在浏览器内识别为文本。
- 插图从原图裁切保留，随文排版，可打印。
- 表格还原为文本行，可朗读。
- 识别结果进入现有块管线，自动获得三档切块、拼音、点读、PDF 导出。

### 非目标

| 不做 | 原因 |
| --- | --- |
| 手写识别 | 模型能力边界，误识别会污染阅读材料 |
| 中英混排、带拼音的教材 | 注音会被当作正文转录，破坏切块与朗读 |
| 自由排版（字号、间距、字体） | 排版权属于三档辅助等级，放开即推翻产品机制 |
| 后端识别、账号、云端存储 | 破坏纯静态定位；无鉴权的 AI 端点必被滥用 |
| 导出 Markdown | 无明确使用场景 |
| 透视校正（四角标定） | 代价高，倾斜不严重的样例收益有限 |
| 强调框（callout）语义还原 | 决策降级为普通段落，见 §11 |

## 2. 架构约束

必须保持现有部署链路不变：

- 无 `functions/` 目录、无 Workers 绑定、无环境变量、无密钥
- `npm run build`（`tsc --noEmit && vite build`）与 `dist` 输出不变
- push 到 `main` 即自动构建发布
- 首屏体积维持约 21 KB（gzip）；OCR 相关代码全部动态 `import()`

新增的静态资源只有 `public/ocr/`（模型与字典）与一个 `_headers`（缓存规则）。二者都不参与构建。

**识别全程在浏览器内完成，图片不上传。**

## 3. 数据模型

```ts
export type Block =
  | { kind: 'heading'; level: 1 | 2; text: string }
  | { kind: 'text'; text: string; captionOf?: string }
  | { kind: 'table'; rows: string[][] }
  | { kind: 'image'; assetId: string; w: number; h: number; alt: string };

export interface CustomDoc {
  blocks: Block[];
  /** 生成时间，用于打印页眉 */
  createdAt: number;
}
```

- `captionOf` 记录图注归属的 `assetId`，仅用于排版（小字号、居中），图注仍留在正文流中参与朗读。
- `table.rows` 保留二维结构，渲染时按行拼成段落，为将来升级为真实表格留出空间。
- 图片二进制不入 `Block`，只存 `assetId`。

## 4. 处理管线

一张图依次经过六步预处理，然后识别，再进入版面推断。

### 4.1 预处理

| 序 | 步骤 | 做法与参数 |
| --- | --- | --- |
| 1 | 解码定向 | `createImageBitmap` + EXIF 方向；像素数 > 24 MP 直接拒绝 |
| 2 | 页边裁剪 | 行列投影找纸张边界，保留 1.5% 边距，去掉桌面与阴影边缘 |
| 3 | 光照归一化 | 大核背景估计（约 1/8 页宽）后做除法，消除渐变阴影 |
| 4 | 灰度拉伸 | 转灰度 + 1%–99% 分位拉伸 |
| 5 | 去倾斜 | 文本行框角度取中位数，限 ±12°；估算不可靠则跳过 |
| 6 | 分辨率闸门 | 长边上限 2048，只缩不放；det 行高中位数 < 24px 时放大 1.5× 重跑 det + rec |

**不执行二值化。** 彩色标题与浅色底纹共存时，全局阈值会切断笔画；PP-OCR 的 det/rec 内部已有归一化，喂灰度原图效果更好。

分辨率闸门的依据：PP-OCR 的流程是「在原图坐标上裁切文本行 → 缩放到固定高度送入 rec」，原图分辨率直接决定 rec 的输入清晰度，主动降采样会降低准确率。

### 4.2 识别

- 引擎：PP-OCRv6 tiny（det + rec + 字典），经 onnxruntime-web 在 Web Worker 中运行。
- 逐页串行，处理完立即释放该页 canvas 与中间缓冲区。
- 输出：每页的文本行（四边形坐标、文字、逐行置信度）。

### 4.3 版面推断

**插图候选框**

1. 将所有文本行框按 10px 膨胀，生成「文本占据掩码」。
2. 在掩码上求空白连通域。
3. 筛选条件：面积 > 页面 3%、宽高比 0.2–5、不贴页边、**框内非背景像素占比 > 1.5% 且方差超阈值**。
4. 按面积降序，每页最多 6 个候选。

第 3 条的像素判据不可省略：样例中存在大片纯空白区域，仅靠「无文本行」会把页尾空白误判为巨型插图。

**裁切收紧**：按非背景像素的外接矩形再 trim 一次，四周留 8px，输出 JPEG q0.85、长边 ≤ 1200px。

**图注归属**：图框下方 1.6 倍行高内、与该图 x 轴重叠超过 60% 的文本行，标记 `captionOf`。并排多图时按 x 重叠度匹配，不按「下方最近」一刀切。

**表格**：同一 y 上存在多个文本行框、且行高一致的区域判为表格；按 y 聚类成行，行内按 x 排序。

**标题**：以文本行高中位数为基准，> 1.3 倍判为 `level: 1`，> 1.15 倍判为 `level: 2`。

### 4.4 组装

| 规则 | 处理 |
| --- | --- |
| 行聚段 | 按 y 间距聚类，间距突变即分段 |
| 中文接行 | 行尾非标点时直接相接，不插空格 |
| 英文接行 | 行尾为连字符则去掉并直接拼接，否则补一个空格 |
| 跨页 | 不合并跨页行，页间强制段落边界 |
| 表单行 | 含连续 3 个以上下划线的行整体剔除 |
| 标点 | 全角标点规范化 |
| 页眉页脚 | 仅 ≥3 页时启用，连续各页首/尾行相似度 > 0.8 即剔除 |

## 5. 编辑器

校对界面为**块列表**，不是富文本，不是 Markdown。

| 阶段 | 能力 |
| --- | --- |
| P0（必做） | 逐块改文字（每块独立 `textarea`，高度自适应）、删除块、上移、下移、插图重新框选、表格在文本/图片间切换 |
| P1 | 合并相邻段落、拆分段落、表格单元格编辑 |
| P2 | 拖拽排序、块类型切换 |

**明确不做**：字体、字号、颜色、分栏、自由排版。

每块使用独立 `textarea` 而非 `contenteditable`：中文输入法、撤销栈、粘贴清洗全部回归浏览器原生行为，无需额外适配。

校对为独立全屏 sheet，顶部固定「取消 / 完成」。不做边看正文边改的分栏。

## 6. 存储

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| `CustomDoc` | localStorage `read-ladder:v2` | 只存块结构与 `assetId`，2 万字约 60 KB |
| 图片 Blob | IndexedDB `read-ladder-assets` / `images` | 5 张约 1 MB |
| 孤儿清理 | 写入新文档时删除未被引用的 asset | 避免长期堆积 |
| 降级 | IndexedDB 不可用（隐私模式）时改为会话内 blob URL | 明确提示「刷新后插图会丢失」 |

**迁移**：读取 v1 的 `customText` 时，按空行切分为多个 `text` 块，`docId` 保持 `custom`。旧字段保留一版兼容读取，不做破坏性删除。

**双入口并存**：粘贴文本 → 按空行切块；上传照片 → 多块文档。两者共用同一渲染与切块路径。

## 7. 渲染改造

| 模块 | 改动 |
| --- | --- |
| `render()` | 外层加块循环；`heading` / `text` 走 `segmentDocument`；`table` 按行拼段后同样走切块；`image` 渲染 `<figure>` |
| `segmentDocument` | **签名不变**，仍只接受 `string`，按块调用 |
| `chunkData` / `speakIndex` | 图片与标题块不占索引，`data-i` 只在参与朗读的文本块间递增 |
| `detectLang` | 拼接所有文本块后判断 |
| 打印 | 进入校对页时即 `await img.decode()` 预热；不依赖 `beforeprint`（其回调无法 await） |
| 打印样式 | `figure { break-inside: avoid; max-width: 100%; }`，打印时限高防跨页 |

| 位置 | 中文 | English |
| --- | --- | --- |

## 9. 限制

| 项 | 值 |
| --- | --- |
| 张数 | 1–5 |
| 单张原始体积 | ≤ 10 MB |
| 处理分辨率 | 长边 ≤ 2048，只缩不放 |
| 格式 | JPEG / PNG / WebP / BMP |
| HEIC | 不转码，提示「请在相册里截图后再上传」 |
| 像素 | ≤ 24 MP |
| 每页插图 | 不限 |
| 识别文本 | ≤ 20,000 字符 |
| 单页字数 | ≤ 4,000（超出说明不是单页打印稿） |

HEIC 走截图变通而非引入 libheif（1.4 MB），因为截图是 JPEG，零成本且用户可理解。

## 10. 失败与边界

| 情形 | 处理 |
| --- | --- |
| 模型下载失败 | 提示「网络不佳，可先用手动粘贴」，保留原文本 |
| 文件损坏 / 0 字节 | 该页标红，可单独重选，不影响其他页 |
| 单页识别为空（去空白 < 10 字） | 标为空白页，提示重拍或手填 |
| 部分页成功 | 保留成功页，失败页单独重试，不整批重来 |
| 全部失败 | 退回手动粘贴，`CustomDoc` 不变 |
| 裁切框越界 | 裁剪到图像范围内，不报错 |
| 裁切区域 < 60×60 | 拒绝该框，提示重新框选 |
| IndexedDB 写入失败 | 保留最近 3 张，其余降级为纯文本，明确告知 |
| 表格行数 > 30 | 提示「建议改为图片保留」 |
| 浏览器无 WASM | 上传入口直接隐藏，老浏览器体验不退化 |

**统一原则：识别结果永不自动覆盖已有内容**，必须经校对 sheet 确认后才写入。

## 11. 决策记录

### 已采纳

| 决策 | 理由 |
| --- | --- |
| 前端 OCR，不加后端 | 无鉴权的 AI 端点必被刷穿免费额度；前端方案无额度、无密钥、图片不出设备 |
| PP-OCRv6 tiny 而非 tesseract.js | 体积更小（约 6 MB 对 11–24 MB），中文更强，det 自带倾斜矫正 |
| 块列表编辑器而非富文本 | 富文本与三档辅助等级的核心机制矛盾，且会与切块渲染产生两套 DOM |
| 块数组 JSON 存储而非 Markdown | 存储服务于程序；Markdown 只适合导出，而导出已取消 |
| 不做二值化 | 彩色标题与浅色底纹共存时，全局阈值会切断笔画 |
| 长边 2048 而非 1800 | PP-OCR 在原图上裁切文本行再识别，降采样直接损失 rec 精度 |
| 表格转文本 | 表格里的字需要被朗读；不可朗读的表格对目标用户无价值 |

### 已否决

| 方案 | 否决原因 |
| --- | --- |
| PP-DocLayout 版面分析模型 | ONNX 权重 125 MB（V3）、约 204 MB（V2），远超 10 MB 预算 |
| 表格结构识别（SLANet 等） | 合计约 +14 MB，同样超预算 |
| Clairic 抽取模型 | 面向字段抽取，不是整页正文转录；单次上限 4 图 |
| 第三方 OCR API | 需服务端保管密钥，图片外发合规复杂 |
| 富文本编辑器（ProseMirror / TipTap / Lexical） | 主包 21 KB → 150 KB 以上，且与切块管线冲突 |
| 强调框 callout 识别 | 决策降级为普通段落；若后续需要，加一个 `kind` 即可，不影响现有结构 |

## 12. 模块划分

```
src/
  blocks.ts         Block 类型、序列化、v1→v2 迁移
  assets.ts         IndexedDB 图片读写与孤儿清理
  render-blocks.ts  块渲染（段落 / 标题 / 表格 / 图片）
  editor.ts         块列表校对 UI
  main.ts           接线，改动最小
  store.ts          增加 customDoc 字段
  ocr/
    engine.ts       引擎加载、识别、释放
    preprocess.ts   六步预处理
    layout.ts       候选框、空白过滤、裁切收紧、图注归属、表格行
    assemble.ts     行聚段、跨页拼接、表单行剔除
public/ocr/         det / rec / 字典 + _headers 长缓存
```

## 13. 实施阶段与验收

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| 0 | 只跑 det + rec，验证 ONNX 输入输出契约 | 英文打印稿字准确率 ≥ 99%，中端手机单页 ≤ 8 秒 |
| 1 | 块模型 + 渲染 + IndexedDB + 打印联动 | 手写 JSON 能正确渲染图文混排并导出 PDF |
| 2 | 六步预处理 | 样例去倾斜与光照归一后识别率不降 |
| 3 | 版面推断 + 框选 UI | 4 页样例产出 19 张插图、1 个 6×2 表格，图注各归其位 |
| 4 | 校对 sheet + 质量守卫 | 低置信度行可定位，空页与表单行正确剔除 |

**回归集**：`images/Page_1.jpg` – `Page_4.jpg`（1428×2000，英文电学讲义）。每次改动比对块数与文字差异。Page 4（8 个图标）与 Page 2（表格 + 并列图注）是压力样本。

阶段 0 若 ONNX 契约不通，回退至 PP-OCRv5 mobile（21.5 MB，仍在前端可接受范围）。

## 14. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| PP-OCRv6 tiny 的 ONNX 契约未实测 | 阻塞阶段 0 | 阶段 0 首先验证输入尺寸、字典格式、CTC 输出形状 |
| 带文字标注的插图漏检 | 插图丢失 | 人工补框；当前样例的图标均带标签，需实测召回率 |
| iOS Safari WASM 内存偏紧 | 长页面崩溃 | 单页降分辨率重试，限制并发为 1 |
| 中文路径无样本 | 中文质量未知 | 本期只验收英文，中文延后到有样张时验证 |
| 弯曲书页的插图变形 | 视觉失真 | 去倾斜只解决整页旋转；靠拍摄引导控制 |

## 15. 未验证事项

以下结论来自官方文档与公开资料，尚未在本机实测，阶段 0 需逐条确认：

- PP-OCRv6 tiny 的 ONNX 权重可用性、输入归一化方式、字典编码。
- onnxruntime-web 在本项目目标浏览器上的 WASM 后端与内存表现。
- 候选框启发式在样例上的实际召回率与误检率。
- 4 页样例的端到端耗时。
